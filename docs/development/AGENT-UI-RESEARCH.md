# BBUI Agent 界面调研与布局建议

日期：2026-09-26。依据官方产品文档及当前源码；以下布局建议是针对 BBUI 的设计判断，不声称是所有 Agent 的统一标准。

## 已落地的小改动

助手执行时的普通正文直接显示 Markdown，移除“执行说明”折叠容器。模型实际返回的 reasoning 保留独立折叠。工具卡片、任务记录和布局的整体调整仍属于以下建议。

## 产品资料

1. [OpenAI：Projects and chats](https://learn.chatgpt.com/docs/projects)：用项目组织相关对话、资料；独立工作目标使用独立会话。会话是沟通和结果的承载单位。
2. [OpenAI：移动端工作与 Queue / Steer](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)：区分等当前轮结束后发送的新指令与执行中纠正方向的指令；排队消息可见。BBUI 当前仅实现前一种，不应假装支持实时干预。
3. [Anthropic：Cowork 与聊天合并](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)：逐步推出统一会话，用户从同一个输入入口提出问题或任务，模型选择工具。不能把尚在逐步推出的体验当作每个账户都已具备。
4. [Manus：在任务内接管计算机](https://help.manus.im/en/articles/11711218-how-can-i-take-over-manus-browser-or-vs-code)：操作环境及人工接管属于任务内部能力，用户可以主动介入。
5. [assistant-ui：Threads](https://www.assistant-ui.com/docs/runtimes/concepts/threads)：成熟的会话状态、列表、切换和元数据接入；继续复用现有 ExternalStoreRuntime，避免引入第二套状态来源。
6. [AI Elements：Queue](https://elements.ai-sdk.dev/components/queue)：区分待发送消息与 Todo，并提供与 PromptInput 组合的示例。可以借鉴其列表语义；只为小组件引入整套重复依赖没有必要。

## 当前界面具体问题

- MainActivity 原生顶栏含 BBUI、画面、设置、停止及状态；WebView 又有会话标题、执行横幅和任务状态，挤占聊天空间。
- TaskRecord 把模型工作记忆中的目标、约束、事实、待确认项和步骤直接当成产品界面，信息过多且可能属于上一个任务。
- 当前会话等待项放在输入框上方，而全局暂停/继续放在侧边栏。用户可以看到“待发送”，却不能在同一位置解决暂停。
- 队列项与会话列表混在同一抽屉，两者分别代表“将做什么”和“以前聊过什么”，导航目的不同。
- 虚拟屏在原生布局中展开会进一步压缩聊天；用户难以分辨所查看历史会话和实际设备当前执行者。
- 即使已提交等待项，仍出现欢迎页，看起来像消息未被接收。

## 建议的层级

| 内容 | 默认位置 | 点击后的内容 |
| --- | --- | --- |
| 会话列表 | 左侧抽屉；宽屏左栏 | 新建、搜索、切换、重命名、删除 |
| 聊天 | 主界面，占主要空间 | 用户要求、执行解释、操作意图、结果 |
| 当前执行 | 标题下的一条紧凑状态条 | 所属会话、进度入口、查看画面、停止；浏览其他会话时可返回 |
| 任务进度 | 状态条中的入口，复杂任务可显示当前一步 | 面向用户的步骤、结果、待回答问题；内部事实/约束放详情页 |
| 等待任务 | 输入框上方仅有等待项时显示 | 当前会话的等待项和取消按钮；“全部等待 N 项”打开全局队列面板 |
| 执行画面 | 顶部固定入口 | 手机全屏视图；宽屏右栏。原生 SurfaceView 保留，明确标注正在执行的会话，并保留接管和停止 |
| 设置与诊断 | 抽屉底部 | 模型、连接、权限、诊断 |

手机聊天页保留一套顶栏；执行状态只有一个主要展示位置。任务记录不再固定压在整个聊天上方。普通执行说明直接显示，思考过程默认折叠；技术性工具诊断进入详情页，操作意图和失败原因在主时间线可见。

队列有三种清楚的文案：正在执行 X、前面还有 N 项、已暂停（原因）。暂停卡片原地提供“继续队列”。没有运行或等待项时不展示空队列模块。队列恢复仍由用户明确操作，不因用户浏览、旋转或应用恢复而自动执行。

任务步骤只在模型确实提供计划时展示，不强制为所有对话生成 Plan；本轮回复结束、等待用户补充、业务目标完成是不同状态，不伪造进度百分比。

第一阶段只调整展示层和入口位置，继续复用 assistant-ui、Pi 会话、原生 SessionController 与 SurfaceView。已按本节层级落地：单一顶栏、独立进度面板、输入框队列入口、会话抽屉和原生全屏/宽屏并列预览。见 `docs/reports/UI-REFACTOR-RESULTS.md`。
