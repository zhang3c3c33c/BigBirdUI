# Agent 任务记录与自主推进

BBUI 保留 Pi 作为唯一 Agent 循环。模型决定观察、操作、提问和完成；手机执行器报告事实。任务记录帮助模型维持目标，不是操作审批或固定工作流。

## 复用

- 使用已锁定的 Pi 0.87.0 扩展 API、会话树、工具结果持久化及 `context` 钩子。
- 任务恢复沿用 Pi 官方 [`todo.ts`](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/examples/extensions/todo.ts) 的模式：从当前会话分支中成功工具结果的 `details` 重建状态。没有额外数据库、调度器或第二套 Agent 循环。
- 界面沿用现有 React、assistant-ui 和浏览器原生折叠元素；Android 继续负责安全桥接与显示缓存。
- 设计参考 Anthropic 的[按需获取上下文、结构化笔记和简洁指导](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)，以及[决策、执行和持久会话分离](https://www.anthropic.com/engineering/managed-agents)。这些原则用于当前架构，并不依赖其托管服务。

## 两个工具的职责

`phone_action` 的顶层 `意图` 为必填非空字符串，最多 80 字符。它由模型填写，描述本次操作目的，不宣称操作成功。缺失或空白在派发前返回格式错误，Pi 将错误交还模型决定如何修正；不向用户发起审批，也不重放旧调用。旧历史缺意图时仍显示操作名，不编造意图。

`task_state` 只读写轻量任务记录。`action: read` 读取当前记录，`action: update` 用 `task` 完整替换。成功结果通过 `details.bbuiTask` 传给模型与界面。记录包括版本、稳定任务编号、目标、模型报告的状态、摘要，以及可选的约束来源、事实、待查信息、步骤、问题和完成依据。新任务使用新编号；补充当前任务沿用编号。

约束来源区分用户明确要求、已有偏好和模型假设。待查信息区分可通过观察获取和需要用户回答。它们都是模型笔记，不会升级为新的用户授权。任务记录不包含截图字节、密钥或原始诊断，不作为输入坐标凭据。

## 决策指导

模型准备提问前，先查看能够自行取得的信息，并推进不依赖答案的工作。例如购物车内容未知，应先展开查看；不能把“我还没看”当成用户必须补充的信息。确实需要用户选择时，再集中说明已确认内容和仍缺少的决定。已有默认项和偏好必须结合其原始适用范围，不能跨任务扩张。

复杂任务在开始、约束变化和关键进展时更新记录；简单任务可直接操作后记录结果，不强制先写计划。步骤由模型调整，不在执行器中编码业务分支。

模型记录 `active`、`waiting_user`、`completed` 或 `blocked`。需要用户时说明问题，完成时说明观察依据，受阻时说明具体障碍。写入状态不会自动中断、续跑或操作手机。未记录结束状态时，界面不猜测其意图，也不自动发起新一轮模型请求。

## 展示与恢复

模型生成状态与任务状态独立。运行期间显示执行中；STOP、接管和错误优先。当前回复结束但没有本轮有效任务更新时，显示“本轮回复结束 · 任务状态未确认”，不能继承上一轮的完成结论。

任务详情默认折叠，可查看模型保留的目标、约束来源、事实、未知项和步骤。只有成功工具结果更新记录，调用参数中的预告不会被提前当作任务完成。

Pi 从当前会话分支恢复原始任务记录，并在模型请求时注入最新笔记；显示缓存不回灌模型。WebView 重建、历史读取、Pi 恢复和任务记录读取都不会重放手机动作。恢复后仍需新观察才能输入，用户 STOP 和设备归属校验保持有效。

## 验证边界

自动化测试使用本地模拟模型与图片，验证实际 Pi 参数校验、工具路由、状态持久化、会话隔离和恢复链路。它们不证明真实模型已经减少提问。真实模型行为评估应另行获得联网授权，并检查：意图填写率、可观察信息是否自主获取、已知约束是否反复询问、完成依据是否匹配画面、停止后是否保留部分进度。
