# scrcpy 接入修复与复核（2026-09-28）

## 已修改

1. **目标屏状态不再被主屏长任务栈挤掉。** `DeviceService` 逐行读取完整系统输出，先按目标显示屏筛选 Activity、旋转和焦点字段，再放入有界缓冲区。通用命令超限、读取异常或尚未读完时明确失败，不返回伪完整的截断结果。目标显示屏缺失时仍禁止回退主屏。
2. **使用 scrcpy 4.1 原生 `keep_active=true`。** scrcpy 按目标显示屏周期调用电源管理器的用户活动接口，解决独立电源组约 60 秒空闲后休眠的问题。不模拟点击、不修改系统休眠时长。保活随该 scrcpy 进程和虚拟屏释放而结束；既有 STOP、接管、锁屏和空闲回收流程继续管理输入权限及资源。
3. **区分编码帧年龄与观察年龄。** scrcpy 只在内容变化时产生新帧，静止页面可以长时间没有新编码帧。新观察重新核对活跃通道、显示屏、窗口、用户、旋转、帧代次和上下文；保留原始帧时间供诊断，但 180 秒观察有效期从本次采集计算。旧截图编号、过期观察和跨环境输入仍被拒绝。
4. **返回真实显示屏电源状态。** 观察附带 `powerState`，已知 OFF/DOZE/挂起状态的画面不能作为新输入凭证，电源状态变化也使旧凭证失效。

## 上游依据与已核对项

- [scrcpy 4.1 设备控制文档](https://github.com/Genymobile/scrcpy/blob/v4.1/doc/device.md)提供 `--keep-active`；不同于只在接电时保持唤醒、修改全局设置的 `--stay-awake`。
- [上游虚拟屏空闲黑屏问题 #6787](https://github.com/Genymobile/scrcpy/issues/6787)记录了同类问题。BBUI 的具体根因另有本机电源组证据，见 [根因报告](../reports/DEVICE-BLOCKAGE-ROOT-CAUSE.md)。
- [scrcpy 4.1 视频文档](https://github.com/Genymobile/scrcpy/blob/v4.1/doc/video.md)说明帧率可变、仅画面变化才产生新帧。`max_fps` 是上限，不是心跳频率。
- [scrcpy 4.1 键盘文档](https://github.com/Genymobile/scrcpy/blob/v4.1/doc/keyboard.md)说明 SDK 文本注入和键盘布局的限制。现有中文输入继续复用 scrcpy 剪贴板协议，等待 ACK、读回核对后向目标显示屏粘贴；不改成依赖主屏焦点的输入方式。
- 当前已经处理视频 EOF/停止、旋转时帧代次变化、控制通道有界等待、动作去重及不确定输入禁止重放；本轮不替换这些机制。

没有升级或修改 scrcpy 服务端：继续使用固定版本 4.1 及现有哈希校验。没有自动重放原任务，也没有调用真实模型 API。

## 验证

- Android 单元测试：app 60、device 24、runtime 7，共 91 项通过。
- 新增单元回归覆盖超过 300000 字符的主屏前缀、目标屏筛选、重复焦点、输出溢出和无换行 EOF。
- 真机：vivo V2366GA，Android 16 / API 36，3 项相关测试全部通过（分两次运行）。
  - 系统休眠时限 60000ms，虚拟屏无输入/观察 72000ms 后仍为 ON；关闭设备后显示屏确实移除。
  - 将测试解码帧接收时间回拨，实际观察的帧年龄为 190869ms；重新观察后只点击调试计数器一次，计数准确增加 1。此项是确定性的旧帧模拟，不声称真实等待了 191 秒。
  - 20 次虚拟屏点击全部命中调试页，主屏悬浮控件点击数为 0；模型截图中悬浮层测试色像素为 0；旧截图和 STOP 输入均拒绝。
  - 中文剪贴板输入留在虚拟屏，未进入主屏输入框。
- 首次空闲测试因脚本在截图后调用 `setStopped(false)`、使截图失效而失败；调整为先改变控制状态再截图后通过，产品校验未放宽。其余两项首次即通过。
- 真机系统 dump 仍超过 37 万字符，但新建测试屏恰好排在主屏之前；“目标屏位于 30 万字符之后”的场景由原现场证据和新增单元回归覆盖，不混称为本次现场顺序。
- 日志和证据保存在忽略目录 `runs/scrcpy-fixes-*.log`、`runs/scrcpy-fixes-dump-evidence.json`，设备证据在应用私有 `files/gate-evidence/`。修复版已覆盖安装，配置和历史保留，测试 APK 验收后移除。
