# BBUI 独立设置页调研与规划

2026-09-27。本轮只做调研和规划，未更改应用行为。

## 依据与现状

- Android 设置设计：长期、低频偏好放设置，常用操作留在功能现场；尊重系统字体与系统权限；数量增加时按分类拆子页。
  https://developer.android.com/design/ui/mobile/guides/patterns/settings
- AndroidX Preference 提供分类、开关、选择项及子页面导航，适合复用。
  https://developer.android.com/develop/ui/views/components/settings/organize-your-settings
- OpenCode 分离供应商连接、模型选择和模型变体；自定义供应商有显示名、地址、模型列表及独立凭证。
  https://opencode.ai/docs/providers/
  https://opencode.ai/docs/models/
- Pi 本地安装版本 0.87.0 的 docs/settings.md 已提供默认模型、按模型思考档位和上下文管理。BBUI 继续复用 Pi，不建立第二套模型运行配置语义。
- Claude computer use 的启用和应用访问设置，与任务中的实际操作分开。借鉴组织方式，不照搬其权限策略。
  https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork

现有 MainActivity.showSettings 是一个 AlertDialog，混合 Provider、协议、地址、模型、密钥、Shizuku 连接、悬浮控制条、本地模拟测试和关闭服务。SettingsStore 仅保存一份加密模型配置。

当前已实现三种协议；已知模型元数据复用 Pi，未知自定义模型目前默认声明图片输入。后者应改为明确的能力信息，不能把协议支持等同于具体模型支持。已知元数据也不能证明任意中转端点完全兼容。

执行画面为 1080×2160 / 480 dpi；模型截图保持像素尺寸，比较 JPEG quality=90 与 PNG 大小后发送较小者。它们目前是实现默认值，不是已有设置开关。

## 页面结构

侧边栏底部“设置”打开全屏独立页面，顶部只有返回与标题。首页每行呈现分类及有用的当前值，不铺开表单，也不加空泛说明。

1. 模型与 API：已保存连接及其模型 → 编辑页；负责配置管理与新会话默认值。日常模型切换和思考档位放输入框上沿。
2. 手机权限：Shizuku 可用/授权状态、悬浮窗权限、通知权限，以及确有必要时的后台运行系统设置入口。
3. 执行画面：虚拟屏界面大小、屏幕规格、截图传输方式。
4. 界面与提醒：执行悬浮控制条、任务提醒；主题扩展后再加入。
5. 数据与隐私：本地存储用量、可清理缓存、模型密钥管理入口及数据发送说明。

帮助与诊断作为单独支持页面，从设置页底部链接进入，承载版本、连接诊断、本地模拟测试、脱敏诊断文件和开源许可。它们是支持工具，不伪装成日常偏好。

页面样式延续暖白背景、绿色强调色、统一原生控件，不把主界面换成另一套视觉语言。首轮项目不多，不增加设置搜索。

## 模型与 API

支持保存多份连接，选一个新会话默认模型。迁移当前配置为第一份连接，保留密钥、Pi 会话和思考设置。每个会话记住自己的模型与思考选择；执行中的一轮保持其启动配置。新增快捷选择后，排队项在提交时保存所选模型与思考配置，而非执行时追随全局默认值。此条是本轮规划对原排队配置规则的明确调整，尚未实现。

连接字段：

- 显示名称，例如“DeepSeek 官方”“公司接口”；内部 provider ID 自动生成，自定义 ID 放高级项。
- API 协议：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages。
- API 地址与 API Key；提供可编辑供应商预设，避免猜测地址或自动更换协议。
- 连接下的模型 ID / 显示名；允许手动输入，不强依赖所有端点提供模型列表接口。

模型字段：

- 设为默认。
- 思考默认值：可随模型保存；日常调整入口移到输入框上沿，仅呈现 Pi 对该模型/适配器支持的选项。显示折叠与模型思考开关是两个概念，不互相修改。
- 能力状态：图片输入、工具调用、思考支持；区分已知元数据、用户声明及测试结果。未知能力不冒充已验证，未知不等于不支持。
- 高级项：未知模型上下文长度、最大输出长度及确实需要的能力声明；常见已知模型用 Pi 元数据。首轮不放 temperature、top_p 等大量参数。

“保存”仅本地校验与保存，不自动请求模型。“发送测试请求”是独立、明确的用户动作：使用固定文字、合成图片和不操作手机的测试工具，分别报告协议连通、图片与工具调用结果；不发送聊天历史或真实手机截图。测试后也不启动用户任务。

## 手机权限

每项显示事实状态与适配当前状态的操作：Shizuku 未启动、未授权、已授权；跳转系统权限页后返回刷新状态。权限设置不是应用自造的开关。

日常发送自动准备连接，不要求“每次先连接”。现有“连接设备”移到帮助与诊断作为故障处理。权限缺失时任务入口可直接定位对应权限项。

不加入自动付款、密码框拦截、固定步骤上限等工具内业务策略。用户以后主动配置的应用范围或任务偏好可另做清晰功能；不因本次设置页改造改变已有授权哲学。

## 执行画面

默认继续使用已验收的 1080×2160 / 480 dpi、竖屏 18:9。

- 普通层可提供“界面大小：标准 / 较大”，首轮只在两种预设真机验收后开放；未验收不显示不可用选项。
- 分辨率、DPI、帧率等放高级项，优先用少量预设，首轮无需任意数字输入。
- 截图传输默认自动压缩，保留当前 JPEG/PNG 比较策略；高级项可提供无损 PNG，暂不提供大量画质滑杆。
- 虚拟屏布局与图片传输质量分开；不把降低图片质量冒充放大界面，也不为实现画质档位偷偷改变坐标。

画面布局参数需重建虚拟屏才生效：保存为待生效，在手机空闲且无人工接管时应用，或用户显式结束当前任务后应用；重建后撤销旧截图/坐标凭证。不能仅以“下一轮任务开始”为条件，因为它可能是当前任务的人工续接。

## 界面与提醒

- “执行时显示悬浮控制条”：长期偏好，开启时若缺权限引导授权；与“目前是否正显示”分开。
- 任务结束、需要补充、异常等提醒；前台避免重复弹出，系统通知权限另有明确状态。系统强制前台服务通知不提供虚假的关闭开关。
- 字体先尊重系统大小。主题跟随系统需要同时补全原生与聊天主题后再开放，首轮保留当前统一样式。
- 思考默认折叠、执行说明展开沿用已确定行为，不新增两套相反开关。

## 数据与隐私

按聊天历史、截图缓存、诊断日志展示存储用量。缓存清理不删除 Pi 会话、不清密钥，也不移除当前执行依赖的文件。删除某会话仍放会话菜单；批量清除历史可后续单独设计，不同数据种类不合成“清除全部”的日常按钮。

模型凭证继续走 Android Keystore 加密存储，不进入聊天 WebView、诊断导出或普通偏好文件。说明“手机执行在本地，所选 API 接收任务文字和必要截图”，避免把本地执行说成全部数据不出手机。

## 帮助与诊断

分别显示模型请求、Pi 运行时、Shizuku、虚拟屏、截图和输入通道状态；不以一个绿灯代表全部可用。

保留本地模拟测试，但明确只验证本地链路；它不能与用户执行争用 Pi 或重置控制凭证，应只在空闲运行。在线模型测试与实际手机输入测试分开。诊断输出脱敏，时间指标区分模型等待与客户端刷新。

“关闭执行服务”移到此处高级区域；在运行/人工接管时明确会停止什么。返回或退出设置本身不停止服务，不改变会话/任务/队列。

## 实现优先级

首轮：独立 SettingsActivity；AndroidX Preference 分类与子页；原生模型表单；多连接/新会话默认模型；输入框模型与思考选择；三协议；能力信息；权限事实状态；悬浮条偏好；帮助诊断；旧设置迁移。

后续：实测过的画面预设、用户可选无损图传、存储分类清理、事件通知偏好；深色模式与个人偏好按需求扩展。未实现项目不以占位开关出现在 UI。

普通偏好复用原生持久化组件；密钥沿用加密 SettingsStore，通过独立适配器接入，不能写入 Preference 默认明文存储。无需新增 Web 设置桥接或重做 Agent 循环。

简单开关即时保存；模型连接的相关字段作为一组校验后保存。只有真正存在未保存编辑才提示放弃，不在浏览、返回或切换分类时额外确认。

## 补充调研：输入区模型与思考选择

用户明确提出模型切换和思考档位放对话框上面。本规划按“消息输入框上沿”落实，保持与输入框一起固定在底部，不随消息滚动；不挤占已经包含会话标题、进度和画面的顶栏。

官方资料：

- OpenAI 官方说明 ChatGPT Work 可从 composer 选择模型与 intelligence level，选项依模型而异。
  https://learn.chatgpt.com/docs/agent-configuration/subagents#choosing-models-and-reasoning
- Claude 模型/effort 菜单位于发送按钮旁；更改从下一次回复生效。其入门文档也说明桌面/网页版在输入框下方、手机版可位于顶部，不能概括为所有客户端位置完全相同。
  https://support.claude.com/en/articles/8664678-change-the-model-effort-and-thinking-settings
  https://support.claude.com/en/articles/8114491-get-started-with-claude
- OpenCode 使用模型与 variant 选择；不同供应商支持的档位不同，不为同一模型的每个档位建立重复模型。
  https://opencode.ai/docs/models/#variants

建议交互：

- 输入框上沿只放两个紧凑入口：“模型名称 ▾”“思考：当前档位 ▾”。执行说明、队列控制、API 字段不挤入该行。
- 模型入口打开底部选择面板，已添加连接分组，当前项勾选；同名模型显示连接名以区分端点，底部“管理模型”进入设置。模型较多时再提供搜索。
- 档位入口只列真实可用选项：支持等级就显示等级，只有开关就显示开关，固定不可调则不提供可点的空控件；不支持时隐藏此入口。不要把所有模型硬映射成低/中/高。
- 思考选择只改变请求配置，不改变聊天思考区域的默认折叠。切换模型时恢复该会话对目标模型的有效选择，否则使用其元数据默认值；不携带上一模型不支持的参数。
- 选择属于当前正在浏览的会话，A 执行时查看 B 并修改 B 不影响 A。新会话使用默认值，已有会话恢复自己的选择。
- 新提交消息记录所选连接/模型/思考及必要配置版本；队列等待期间不随会话选择漂移。密钥仍由原生安全存储管理，不写入 Web 状态或队列展示。缺失的连接应明确报错，不静默改用另一个供应商。
- 进行中的一轮不因点选而中途换模型。新选择用于随后提交的消息；“立即补充”属于当前执行，仍使用当前执行模型。明确点击“继续任务”时读取该任务所属会话的选择，不能读取正在浏览的另一会话。
- 模型/协议切换继续复用 Pi 会话及其适配器；实现时回归三协议的历史、工具与思考兼容。切换本身不发请求、不重放手机动作。
- 回复详情可查看本轮实际模型与档位，输入框显示的是下一次提交的选择；无需为每条消息增加常驻技术小字。

本节属于 BBUI 设计建议；排队绑定、人工续接等细节不能直接视为上述产品的共同实现。
