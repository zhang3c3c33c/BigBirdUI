# 统一手机操作工具

> 内部开发资料：此入口用于调试或历史兼容，不属于对外支持的使用方式。用户使用 Windows 桌面应用或 Android 本地应用，见 [项目首页](../../README.md)。

入口：`phone_action(操作, 参数)`。一次操作自动返回执行状态、截图、前台应用、截图编号和耗时。决策由调用模型完成。本文描述内部执行器接口。

2026-09-26 起使用分离的执行/观察结果契约，详见 [TOOL-CONTRACT.md](../contracts/TOOL-CONTRACT.md)。本文件以下命令和屏幕管理示例适用于桌面后端；安卓仅暴露其实际支持的单屏能力。

现已接入 Pi，并支持多个 scrcpy 虚拟屏幕并行。运行 `npm run phone`，完整启动与架构说明见 [PI-HARNESS.md](PI-HARNESS.md)。MCP 与 JSONL 调试入口均使用屏幕会话路由；JSONL逐行调试仍串行处理请求，并行客户端使用同一个 MCP 进程。

## 启动

```powershell
# 在仓库根目录执行
.\.venv\Scripts\python.exe -m bbui.unified_mcp
```

MCP 配置见 `docs/development/examples/mcp.unified.example.json`。命令行调试可运行 `python -u -m bbui.unified`，每行传入一个 UTF-8 JSON 请求，进程保持连接；`结束会话` 关闭连接并退出。不要每步重启进程。

## 参数

`执行后等待毫秒` 可选，省略为 0；传入时必须是 0～30000 的整数。字符串、小数、布尔值或越界值会在执行前返回未派发结果。

执行顺序：**执行动作 → 等待指定毫秒 → 采集截图 → 返回结果**。等待时长由模型依据页面决定。`等待` 操作优先使用 `时间` 作为总等待时长，否则使用后置等待字段，两者不累加。重复动作请求不重新执行，返回原执行事实并尝试取得当前截图。

下表列各操作的专用参数。

| 操作 | 专用参数示例 |
|---|---|
| 查看 | `{}`；可选 `读取节点:true` |
| 等待 | `时间:500` |
| 点击／双击 | `位置:[540,900]` |
| 长按 | `位置:[540,900], 时间:700` |
| 滑动 | `起点:[540,1800], 终点:[540,700], 时间:400` |
| 拖拽 | 同滑动，另加 `按住时间:600` |
| 放大 | `中心:[540,1000], 初始指距:200, 结束指距:400, 时间:400` |
| 缩小 | `中心:[540,1000], 初始指距:400, 结束指距:200, 时间:400` |
| 输入内容 | `内容:"影视飓风"`，向当前焦点插入，不清空原文 |
| 删除内容 | `次数:1`，退格删除 |
| 全选 | `{}`，当前控件须支持 Ctrl+A |
| 按键 | `键名:"返回"`，另支持主页、最近任务、回车、删除、向前删除、上、下、左、右、音量加、音量减、唤醒 |
| 打开应用 | `包名:"tv.danmaku.bili"`，默认允许所有包；config.local.json 的 blocked_packages 中指定的包除外 |
| 列出应用 | 无专用参数则返回当前 Android 用户全部已安装包；可选 `关键词:"bili"`（包名子串）、`包含系统应用:false`；只读，无截图 |
| 系统面板 | `面板:"通知"`，或快捷设置、收起 |
| 创建屏幕 | `屏幕会话:"calc", 包名:"com.android.bbkcalculator"`；可选宽度、高度、密度，返回本屏截图 |
| 列出屏幕 | 无专用参数，列出当前进程管理的屏幕；不返回截图 |
| 关闭屏幕 | `屏幕会话:"calc"`；释放虚拟屏幕及连接，不返回截图 |

所有时间单位为毫秒：动作自身的 `时间`／`按住时间` 上限5000，截图前的 `执行后等待毫秒` 上限30000，两者独立。坐标基于本次返回截图的原始尺寸，不能直接使用聊天预览的缩放坐标。缩放是双指间距变化，不保证内容恰好按相同比率缩放。

通用参数：桌面 `屏幕会话` 默认 `main`；`截图编号` 必须来自本屏最新观察；`动作编号` 可选，用于去重；`读取节点` 默认 false。虚拟屏幕不支持读取节点，存在虚拟屏幕时 main 同样拒绝读取节点，避免全局无障碍树串屏。列出／关闭不返回截图，也无需等待参数。

```json
{"操作":"查看","参数":{"执行后等待毫秒":0}}
{"操作":"输入内容","参数":{"内容":"影视飓风","截图编号":"上一步查看返回的编号","执行后等待毫秒":1000}}
{"操作":"按键","参数":{"键名":"回车","截图编号":"输入内容返回的新编号","执行后等待毫秒":3000}}
```

返回 `执行` 与 `观察` 两组独立事实。前置校验错误返回未派发并尽量附上当前画面；已派发后观察失败不会改写派发状态。派发不代表业务完成；结果不确定时先查看，不盲目重复。画面可能尚未加载完成，由模型决定继续查看、等待或操作。

## 本版性能和实现

`列出应用` 示例：

```json
{"操作":"列出应用","参数":{"执行后等待毫秒":0}}
{"操作":"列出应用","参数":{"关键词":"bili","包含系统应用":false,"执行后等待毫秒":0}}
```

桌面返回 `用户编号`、`已安装总数`、`返回数量`、`应用列表` 和查询耗时；每项包含 `包名`、`系统应用`、`允许操作`、`可启动`、`启动入口`。数据来自当前 Android 用户，默认包含没有桌面入口的包。`可启动` 只表示有 MAIN/LAUNCHER 入口，不保证启动结果。桌面查询不提供应用中文名称，不改变禁止列表，不创建屏幕，不消耗截图编号；纯文本模型也可以调用。无需等待字段。

- 单进程常驻 UIAutomator 和 scrcpy 控制连接，不再每步推送、启动 scrcpy。
- 默认只返回截图与上下文，UI树按需读取。
- 动作内直接获取结果画面，不需要模型另调截图接口。
- 手势结束或停止异常时尝试抬起全部手指。传输完全断开时无法保证释放事件抵达设备。
- 一个设备由一个运行时管理；运行时内按屏幕串行、跨屏并行。保留有效观察校验与动作记录；像素变化作为证据，异常不自动重放输入。
- 输入前核对焦点应用；中文使用 scrcpy 剪贴板并读回核对，会更新手机剪贴板，不改变输入法。
- 主屏按需截图；虚拟屏幕使用独立视频流持续解码。动作后等待指定时长再获取画面，固定等待不保证页面加载完成。
- 设备断线后丢弃失败连接；先查看再决定下一步，不自动重放输入。当前会话退出时关闭 scrcpy。

停止新输入可以从另一个终端执行旧兼容命令 `python -m bbui.cli stop`；恢复为 `resume`。

Pi运行时占用设备期间，使用 `/phone-stop` 和 `/phone-resume`。旧CLI恢复命令会被运行时设备锁拒绝；也可先退出运行时再恢复。
