# 手机工具契约

本文件描述 2026-09-28 工具改造后的行为。审查过程见 `docs/contracts/TOOL-DESIGN-REVIEW.md`，系统与 Agent 扩展接口见 `docs/contracts/TOOLS-IMPLEMENTATION-CONTRACT.md`。

## 职责

工具执行操作并返回事实。模型结合用户任务、既有偏好、画面和结果选择后续步骤；工具不替模型决定必须人工接管、业务是否成功、任务是否结束。

用户已明确批准：密码框类型不再一律禁止自动输入；固定像素差阈值不再拒绝输入；启动后是分身选择等中间页时返回画面继续判断。这不增加任务授权，也不解除用户停止、设备归属或输入准确性校验。

## 能力

安卓当前只有宿主管理的一个 virtual 屏幕。模型可用：查看、等待、点击、双击、长按、滑动、拖拽、放大、缩小、输入内容、删除内容、全选、按键、打开应用、列出应用、列出屏幕。创建/关闭屏幕、系统面板和读取节点不在安卓模型 schema 中；宿主仍负责连接、停止、接管和释放。

桌面除上述操作还支持创建/关闭命名屏幕及 main 系统面板。命名屏幕可以跨应用；同一个应用已被另一受管屏幕使用时仍报告归属冲突，避免隐式迁移。创建屏幕可不指定应用；无画面时如实返回观察失败，之后可明确启动应用。屏幕资源数量通过 `max_virtual_screens` 配置，默认 3。

旧 MCP 只暴露 observe/act/stop；恢复用户 STOP 由宿主命令负责，不暴露模型可直接清除 STOP 的 resume 工具。

## 参数

### 安卓系统与 Agent 扩展

Shizuku 是全应用门槛。掉线或授权失效会停止执行、使待回答问题失效、暂停队列并返回欢迎页；恢复授权不会自动重跑。绑定系统服务不创建虚拟屏，只有 GUI 观察、操作或应用启动按需创建。

- `system_apps`：当前用户的应用列表、详情、启动入口、启动、停止、启用/停用、本地 APK 安装更新、卸载、清数据和系统允许的运行时权限管理。
- `system_notifications`：按应用分页列出、详情分页、延后提醒和恢复延后。没有清除、快捷回复或按钮执行能力。
- `system_clipboard`：读取、写入、清空文本；非纯文本剪贴板如实标记，不依赖视频连接。
- `system_files`：当前用户共享目录的列表、元数据、名称搜索、文本分页、写入、目录创建、复制、移动、重命名和删除。覆盖及递归为显式参数，不提供任意 Shell 或私有应用目录访问。
- 联网搜索固定使用设置中选定的博查或百度，不隐式回退；网页提取和结果分页保留，浏览器、Cookie、下载视频和额外总结模型未启用。
- 用户记忆在本机跨会话共享，设置与模型操作同一份长期 Markdown；修订冲突保留草稿，删除会话不删除记忆。
- `ask_user_question` 等待显式答案或取消，占用当前执行位；普通输入入队。问题绑定会话、运行代次和请求编号，重复或过期答案不会重新执行。

系统修改复用 STOP、接管、动作编号去重和执行通道故障隔离；只读查询不依赖截图。安装可触发设备原有系统确认；超时报告未知事实，不自动重试。详细正文保留在模型结果和 Pi 历史，聊天卡片只保留有上限的摘要。

### GUI 参数

- `意图`：可选展示信息，不改变派发、去重或执行权限，不包含敏感凭据。
- `执行后等待毫秒`：可选，默认 0，最多 30000。`等待` 的 `时间` 是总等待时长，不与后置等待相加；不传任何等待值时默认 0。不要把未指定时长的等待当作保证页面已加载。
- 坐标操作引用同屏最新有效截图编号，坐标为原图像素。旋转、屏幕代次或页面上下文不一致时，本次不派发并尽量返回新观察。
- 打开应用使用 `包名`，可选 `启动组件` 必须属于该包。安卓不依赖旧截图坐标，只依赖有效的屏幕归属和当前输入状态；桌面仍在其观察驱动契约内执行。
- 安卓应用查询按包名或已取得名称筛选，桌面按包名筛选；`包含系统应用` 默认 true。安卓返回当前用户已安装包、系统标志及全部 launcher 入口。名称取得失败时省略，不假称完整枚举厂商分身。
- 操作参数范围是明确能力上限。输入每次最多 2000 字、删除次数最多 100、手势时长最多 5000 毫秒；不静默截断。模型可根据明确反馈调整调用。
- 安卓输入内容使用 scrcpy 定向粘贴，全选和删除使用同屏定向按键。三者不要求全局输入法属于虚拟屏；校验最新观察、目标屏/用户/焦点窗口身份、屏幕代次、STOP 和人工接管。无法确认目标窗口时返回未派发和新观察，不回退主屏。粘贴在当前光标/选区插入，不保证末尾追加或替换全部文本。

## 结果

Pi `content` 仍包含文本与图片块；安卓还用 `details` 传递同样的结构。桌面 MCP 首个文本块即结构化结果，Pi bridge 将其投影到 details。

```json
{
  "动作编号": "...",
  "执行": { "状态": "已派发" },
  "观察": { "状态": "已取得", "截图编号": "..." },
  "屏幕": { "displayId": 61, "package": "com.vivo.doubleinstance" },
  "目标应用在前台": false
}
```

`执行.状态` 的含义：

| 值 | 含义 |
| --- | --- |
| 无需派发 | 查看、等待或查询，不涉及输入 |
| 未派发 | 本次输入没有提交，如参数或观察校验拒绝 |
| 已派发 | 对应输入/系统请求已提交，不保证页面或业务效果 |
| 部分派发 | 已确认某些子步骤提交；报告可证明的进度 |
| 未知 | 无法确认派发结果；不得后台重放 |

`观察.状态` 独立为已取得、失败或未请求。已派发后截图失败仍保持“已派发”。错误可包含阶段、原因和局部诊断；正常业务拒绝不等于通道故障。

安卓额外返回控制/视频通道事实、用户停止和接管状态。视频连接存在不保证本次截图成功，应结合观察结果。截图元数据缺失或上下文不一致时仍尽量返回图，并标记不可用于输入；不能将旧图签发为新页面坐标依据。视频帧时间和年龄用于区分旧缓存帧与最新观察。

安卓系统查询尚未创建 scrcpy 时，`通道.控制=未创建`、`通道.视频=未创建`，表示资源按需分配，不是执行故障，不暂停任务或队列。真实输入/连接故障优先报告 `控制=不可用` 和故障原因；后续查询成功或本轮结束不能自动解除故障隔离、STOP 或接管。

`全局输入法` 只描述诊断事实，`用于派发校验=false`，匹配失败不代表 scrcpy 定向粘贴不可用。`文字输入.写入结果` 明确说明未自动读回；已派发只证明控制请求已提交，模型根据执行后画面确认文字及业务效果。粘贴键发送前的目标变化或 STOP 保持未派发；剪贴板 ACK 不作为输入框写入成功证据。

重复动作编号不会重放，返回原动作已知执行状态及本次未重放标志。不能把重复调用理解为原动作从未执行。

启动工具只提交一次启动请求，然后返回实际前台和画面。分身选择器、登录页面、权限提示和加载页面不需要厂商专用决策分支；模型据图决定下一步。没有后置前台证据时，不填充一个猜测的“目标已在前台”。

## 停止与技术恢复

用户 STOP/人工接管优先。模型不能解除用户停止。停止不撤销已经发出的输入，也不应抹掉此前已知执行事实。

业务拒绝、旧观察和单次截图失败不使健康通道失效。HTTP/RPC 传输不确定则单独隔离新输入，保留仍可用的查看/等待/查询。一次成功截图不证明旧请求已结束，因此不能靠截图清除隔离。

安卓输入故障由宿主下一次明确启动任务时处理：关闭旧 Pi、释放异常设备连接，再建立新代次。新连接不重放旧动作，模型必须重新观察。用户停止仍由宿主授权流程控制。

桌面将传输隔离记录在设备运行目录的 `INPUT_UNCERTAIN`，与 `STOP` 分离。`/phone-resume` 只处理用户停止，不清除未知输入隔离。用户可调用 `/phone-recover`：确认旧 MCP 进程退出、旧调用结束、设备租约释放后，仅清除属于本宿主的隔离标记，再重连、列屏并观察主屏。它不清除用户 STOP、不创建虚拟屏、不启动应用或重放输入；旧虚拟屏不再由新会话管理，需要时明确重新分配。缺少退出证据、存在其他宿主标记或租约冲突时不会清除隔离。

## 展示

Pi 调用 `phone_action` 时必须提供非空顶层 `意图`（最多 80 字符），描述本次准备做什么；意图不传入设备参数。缺失时在派发前返回格式错误，由模型修正。新增的 `task_state` 仅保存模型的目标、约束、进展和状态，不操作手机、不决定审批或任务续跑；详见 `docs/development/AGENT-TASK-DESIGN.md`。

工具调用返回不等于业务完成。卡片显示“已派发”“未执行”“部分派发”“结果待确认”“已观察”“观察失败”等事实组合，旧记录显示“已返回”；不因调用结束就显示成功勾。正文、思考、工具意图仍分别展示。

工具内不再设固定 100 次调用后必须用户继续的规则。任务预算如有需要由宿主管理；模型按任务进展和用户指令决定继续、询问或结束。
