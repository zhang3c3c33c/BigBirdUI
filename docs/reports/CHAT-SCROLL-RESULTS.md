# 问题卡片与聊天滚动优化

2026-09-28，主代理调研、子代理实施、主代理审查验收。

## 调研与采用方式

- [assistant-ui Thread](https://www.assistant-ui.com/docs/primitives/thread)：已有消息列表、分页配合和“用户向上阅读时不追底”的视口机制。继续复用本项目安装的 0.15.22，不替换 Agent 循环或自行写虚拟列表。
- [AI Elements Tool](https://elements.ai-sdk.dev/components/tool)：工具展示按状态区分，支持折叠和结果/错误展示。它并不要求完成后默认收起；BBUI 的“回答后收起”来自用户明确要求。
- [Chrome 主线程优化建议](https://developer.chrome.com/docs/lighthouse/performance/mainthread-work-breakdown)：减少输入处理器与主线程工作，合并高频事件。这里优先消除全量存储和桥接开销，而非先改动画或堆 CSS。
- 已核对本机 assistant-ui 的消息转换缓存、Markdown 缓存及视口源码。复用稳定消息引用，避免无关快照使整段消息或所有工具卡片重新处理。

## 已确认的根因

1. 当前会话有 51 条展示消息，默认页面仅显示最近 40 条。已回答问题的原工具消息在分页之外，但末尾兜底代码没有检查问题是否结束，因而把完整已回答表单放到总结下方。
2. 滚动每个事件均跨 WebView 桥发送 viewState；原生再按 200ms 间隔把所有会话的完整展示历史投影并保存，阅读位置触发了远超其需要的工作。
3. 普通工具卡片订阅完整问题快照，并为每张卡片反复扫描消息；快照即使未改变消息，仍产生新的 messages 数组。

## 实施范围与验收边界

- 已结束问题只留在原工具调用的位置，默认折叠，展开看原问题和实际答案；仅仍可回答的未绑定问题允许临时兜底。历史分页不丢问题，也不把旧问题搬到末尾。
- 合并滚动位置/草稿桥接，在切换和页面生命周期边界保存尾值；保留上读不追底、分页锚点、去重及提交确认。
- 阅读位置和输入草稿使用小型 AtomicFile 缓存，按每会话版本与主会话文件合并；任务和消息仍使用既有可靠提交路径，缓存不能重放任务或覆盖较新草稿。
- 真机验收使用隔离长历史样本，不调用真实模型，不执行用户任务。安装前后校验原始 Pi 会话、记忆与加密配置。

## 同会话真机前后测量

vivo V2366GA / Android 16，系统 WebView 153.0.8010.36。同一真实会话、最近 40 条消息，前台 8 秒 requestAnimationFrame 驱动滚动，测量结束恢复原位置：

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 原生 DOM scroll 事件 | 393 | 481 |
| viewState 桥接消息 | 393 | 9 |
| 渲染帧间隔 p50 | 16.7 ms | 16.7 ms |
| 渲染帧间隔 p95 | 66.8 ms | 16.8 ms |
| 帧间隔最大值 | 83.6 ms | 16.8 ms |
| 超过 25 ms 的帧间隔 | 33 | 0 |

这是一条固定会话与滚动过程的采样，不等同于所有设备的 FPS 保证。第一次测量因应用退到后台、WebView 暂停而连接超时，未计入结果；回到前台后取得以上基线。

修复后仍为同一会话最近 40 条消息；错误的末尾问题表单消失，内容高度从 7491 降为 6919 CSS 像素。DOM 事件次数不同来自实际采样帧数不同，不用于声称吞吐提升比例。桥接次数和采样帧间隔是本次观测结果。
