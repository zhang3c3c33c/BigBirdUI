# 日程工具交付与验收

日期：2026-09-28。子代理实现 Android 后端、Pi 工具与协议测试、聊天展示与真机测试；主代理审查、集成、安装并执行手机验收。

## 已交付

- Android 新增 `system_calendar`：列日历、按时间范围查询实例、详情、新增、修改、删除。
- 支持标准 RRULE 重复、全天事件和提前分钟提醒；可取消重复、清空提醒。修改与删除要求明确 `scope: series`，本轮不支持仅一次或本次以后。
- 复用 Shizuku shell UID 2000 与 Android Calendar Provider，显式绑定当前 Android 用户；无需 GUI、截图或虚拟屏。未开放任意 Shell/SQL。
- 保留 STOP、动作编号去重和独立写入回执。事件与提醒批量写入；写入后的回读失败不抹掉事件编号，不自动重试。
- 查询支持分页和传输预算；聊天只展示模型意图及摘要。桌面后端未实现，故不注册该工具。

## 审查修正

- 整系列修改范围必须显式提供；查询详情也校验可选的日历身份。
- 依据目标日历检查可写性、提醒数量和允许的提醒方式。
- 省略字段保留；取消重复同时清理旧的 RDATE/EXRULE/EXDATE。避免把截断的规则用于重建日程。
- 写入标准持续时间，兼容读取已有格式；保持 JSON null 和 Emoji 处理正确。
- Pi 真实工具循环通过 `tool_result` hook 标记日程失败，保留结构化回执；不把正常的业务拒绝变成连接故障。

## 真机验证

设备：vivo V2366GA，Android 16 / API 36，Shizuku adb 模式 UID 2000。

`CalendarIntegrationTest`：1 项完整端到端测试通过。

- 在普通本地可写日历创建带唯一标记、未来日期的临时事件，中文、Emoji、逗号、换行回读一致。
- 每日重复三次，Instances 返回准确的三次起止时间。
- 提前 15 分钟提醒写入成功，修改为 30 分钟并核对。
- 重复动作编号保留同一事件回执，不产生第二个事件。
- 取消重复及清空提醒后，只剩一次实例且提醒表为空。
- STOP 阻止删除；测试恢复后确认事件仍在，再删除并确认无测试实例残留。

## 未验证与边界

- 未调用真实联网模型或搜索 API；本地模型样本不能证明真实模型的日期理解或自主决策质量。
- 已验证提醒记录写入，未等待实际到点通知或响铃。
- 仅本机验证；其它 OEM/Android 版本的隐藏 API 和 Calendar Provider 兼容性仍需设备验证。
- 不支持修改单次重复例外；已有 RDATE 事件若需改变时间，须明确重复规则，防止默默改变语义。
- 联系人、短信、通话记录、媒体索引等为后续候选，详见 `docs/guides/NON-GUI-CAPABILITIES.md`，本轮未接入。
