# Windows 桌面验收记录

日期：2026-09-28。交付 Windows x64 免安装 ZIP；本次没有制作或验收 macOS。

## 实现范围

共享 React/assistant-ui 聊天组件、Pi 运行时与工具模块；Electron 提供会话、队列、加密配置和设备宿主。独立 Python 执行器跨会话保持设备和屏幕，系统工具复用 Android Kotlin 实现，经 ADB app_process 运行辅助 JAR。手机无需安装 BBUI APK 或运行 Shizuku。

包括流式聊天、Markdown、思考折叠、工具事实、会话管理、分页/阅读位置/草稿、任务进度、补充指令、FIFO 队列、提问、主屏及多虚拟屏预览、人工接管、停止/明确续接、设置、模型发现/测试、搜索、记忆、手机应用/通知/剪贴板/共享文件和截图历史。列宽可调整、收起和放大，支持悬浮停止按钮。

凭据使用 Electron safeStorage。Windows 首次保存等待 Electron 的 DPAPI 加密状态落盘后才确认成功，覆盖保存后立即崩溃的恢复场景。关闭主窗口先停止任务、保存数据、等待设备执行器退出，再正常退出 Electron；重启不自动重放。

## 桌面预览流畅度修复（2026-09-28）

按用户要求，先调研，由子代理实现，主代理独立审查及真机验收。行业参考：[scrcpy 视频/控制分离和立即显示设计](https://github.com/Genymobile/scrcpy/blob/v4.1/doc/develop.md)、[可变帧率与无缓冲默认行为](https://github.com/Genymobile/scrcpy/blob/v4.1/doc/video.md)、[Tango 的浏览器视频解码器](https://tangoadb.dev/scrcpy/video/)、[Electron MessagePort 流式通信](https://www.electronjs.org/docs/latest/tutorial/message-ports)。

本次复用现有 scrcpy/PyAV 连续解码，采用只取最新帧、无积压的方式；保留现有宿主 IPC 和 JPEG 预览，未引入第二套 ADB 会话或 WebCodecs 管线。原瓶颈是每帧两次 context（合计四次 ADB 系统查询）以及请求结束后额外等待 200 ms。现改为 30 FPS 源上限及扣除请求耗时的前端刷新节奏，无新帧时不重复压缩、传输图片；隐藏或收起预览停止请求。

视频帧及序号、编码会话代次原子读取；人工输入检查屏幕、视频实例、代次和尺寸，并在重新观察前后确认代次及目标窗口。旋转或重建后旧帧不能输入。STOP、控制权、模型观察校验与动作去重仍走原执行器。预览不生成模型观察编号。输入失败提示单独保留，不会被下一帧清除。

主代理审查发现并要求修复首次主屏没有 preview 属性的问题，并要求补足同尺寸编码重启及输入错误提示持续显示的回归。Python 74 项、桌面控制/状态 9 项、Pi 11 项、根目录及共享 UI TypeScript、浏览器预览测试通过。

真机为 vivo V2366GA / Android 16，使用隔离桌面配置，重复展开/收起通知栏 12 次；以实际 Electron img load 事件统计显示，测量结果不是 RPC 次数，也不是物理触摸到显示的端到端延迟。测试后收起通知栏并关闭执行器。

## 人工输入延迟（2026-09-29）

用户澄清问题为接管后的操作响应慢，而非接管过程。真机分段确认旧人工点击复用完整模型操作流程：派发前 6 次 context、派发后 2 次，每次 context 有两条 dumpsys 查询，另有截图保存、像素差与观察落盘。前端等待整个输入返回，其间阻止重复输入，旧版因此约 1.7 秒才结束一次调用。

参考 [scrcpy 官方输入与视频独立通道](https://github.com/Genymobile/scrcpy/blob/master/doc/develop.md)，人工路径直接复用现有控制连接与触摸/按键/粘贴实现，保留 2 次目标上下文核对，去掉模型观察和截图落盘。中文粘贴在剪贴板确认后仍核对窗口。模型输入路径保持原观察校验；人工输入使旧模型观察失效，重新交给 AI 后必须重新观察。

人工路径保留设备锁、动作去重、禁止应用、焦点用户、屏幕及视频代次/尺寸和 STOP。每次新触摸包前检查控制权，旋转、换流或撤权时停止后续包并向原连接抬手。独立子代理审查发现并修复释放控制权后旧人工线程的校验问题，以及隔离记录写盘失败可能遮蔽已知派发事实的问题。前端本轮没有为输入增加队列或乐观成功状态。
