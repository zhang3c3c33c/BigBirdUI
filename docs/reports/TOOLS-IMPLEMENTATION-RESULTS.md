# 系统能力与 Agent 工具交付记录

日期：2026-09-28。手机：vivo V2366GA，Android 16 / API 36，Shizuku adb 模式。

## 实现

- Shizuku 为统一门槛；权限失效停止执行和提问、暂停队列、退出操作画面并返回欢迎页。恢复授权不自动恢复任务。
- 系统连接与虚拟屏分离。系统查询、文件、剪贴板、搜索、记忆和提问不创建显示屏；GUI 按需创建。
- 接入应用管理、通知、文本剪贴板、当前用户共享文件四组结构化工具。沿用动作去重、STOP、接管、执行凭证及不确定输入隔离。安装只接受本地 APK，系统命令参数固定，无通用 Shell。
- APK 固定打包 pi-web-access 0.32.0、pi-memory 0.4.2、@jyooi/pi-ask-user-question 0.1.1。上游复用及构建适配见 [UPSTREAM-TOOLS.md](../../pi/android/UPSTREAM-TOOLS.md)。
- 设置新增联网搜索供应商与加密密钥、用户记忆编辑。博查与百度明确选择；不自动回退。记忆读写共享锁和版本校验，冲突保留用户草稿。
- 聊天提问卡片支持多题、单选、多选和自由输入；等待占用当前执行位，普通消息排队。草稿原生持久化，历史按稳定消息与请求编号关联，工具调用 ID 复用不会串卡片。
- 原始工具正文不进入聊天快照；界面只保留有限摘要。搜索响应、网页及记忆有大小限制，长结果分页；剪贴板读取分页，系统写入和序列化请求受 Binder 传输上限约束，超限在派发前拒绝。截图及密钥不进入新增卡片状态。

真机发现并修正：单 APK 标准输入安装参数、scrcpy 兼容库在 Binder 线程初始化造成的崩溃。应用安装遇到 vivo 自带确认页时由验收人员确认，产品不绕过系统确认；未知执行结果不会自动重试。

通知恢复的系统限制已定位：当前 vivo Android 16 的 `cmd notification unsnooze` 先输出派发信息，随后以退出码 0 输出 `Permission Denial: getIntentSender() ... uid=2000 is not allowed to send as package android`。通知列表、详情和延后可用；恢复在本机被系统拒绝。工具会解析多行错误并报告系统原因，不把退出码 0 当作成功，不申请另一套权限或自动重试。

- 原因：系统查询不创建 scrcpy，但 `controls == null` 被报告为“控制不可用”，会话层因此错误暂停队列并保留继续任务标记。实际查询成功，下一步创建虚拟屏后仍能执行。
